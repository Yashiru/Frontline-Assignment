# Frontline voice-agent evaluation design

## Scope and risk priority

This suite protects the carrier call path: identity verification, load lookup, load presentation, negotiation, persistence, termination, and human transfer. Risks are ranked by business impact:

1. **Confidential price leak:** goal or ceiling disclosed in digits, comma/decimal variants, or spoken freight shorthand. The prompt interpolates both values and claims all numeric/spelled forms are forbidden (`shared/src/negotiation_prompt.py:34-49`), while voice guidance explicitly encourages forms such as “twenty-two” and “eighteen-five” (`voice-agent/voice_prompt.py:82-89`).
2. **Economically harmful negotiation:** agreement above ceiling, wrong `above_max`, Zone 1 countering upward, excess concessions, or negotiating in no-rate mode. Zone 1’s specific rule overrides the general two-round rule (`shared/src/negotiation_prompt.py:80-106`); no-rate says accept the first bid (`shared/src/negotiation_prompt.py:57-64,71-77`).
3. **False/incomplete agreement:** recording before explicit acceptance or without contact name and phone. The prompt requires confirmation and both fields (`voice-agent/voice_prompt.py:141-150`), but the handler validates contact only for `above_max` (`voice-agent/call_helpers.py:665-716`).
4. **Fabricated lookup outcomes / wrong tool sequencing:** claiming an MC or load result without its matching successful tool result, or negotiating before verification and load retrieval. A successful load lookup swaps the system prompt and stores load context (`voice-agent/call_helpers.py:589-638`).
5. **Wrong termination:** missing, premature, duplicate, or outcome-inconsistent `end_call`; the handler accepts enumerated reasons but does not guard agreement sequencing (`voice-agent/call_helpers.py:764-843`).
6. **Transfer-policy violation:** transfer before verified identity and successful load lookup, or transfer after closure. The schema and runtime guard require a loaded load, but not verified identity (`voice-agent/tool_definitions.py:105-127`; `voice-agent/transfer_tool_handler.py:62-117`).

## Three evaluation layers

**L1 — prompt-contract tests.** Table-driven fixtures render the real prompts for four load shapes—priced 1400/1600/1800, no-rate, special instructions, and comma-string rates—across the two implemented initial states: unknown carrier and known/preverified carrier. Assert exact policy clauses, normalized values, tool availability, and absence of contradictions except findings explicitly documented below. Rate normalization accepts numeric and comma strings and maps missing/invalid values to zero (`shared/src/load_normalization.py:68-81,229-233`). Future coverage should add phone verification disabled, preverified/denied then MC reverified, and the remaining confirmation transitions.

**L2 — real-handler contract tests.** Invoke real `verify_carrier`, `get_load_context`, `record_agreement`, `end_call`, and `TransferToolHandler` handlers with fake Highway/Supabase/Daily/orchestrator/task callbacks. Assert prompt replacement after lookup, exact persisted agreement arguments, rejected invalid/missing values, `end_call` guard/state/EndFrame behavior, and transfer guard/routing/scheduling. Fakes record calls and return fixtures; they never use network, production credentials, or side effects.

**L3 — scenario evaluations.** Each versioned scenario contains a load fixture, scripted carrier turns parameterized by opening bid, walk-away utterance, firmness, human request, or bad/unknown MC attempts, and an expected outcome. The script is deterministic and does not adapt to intermediate agent offers. A model client produces agent turns from the real prompts and schemas, with tool calls dispatched to real handlers over fake backends. The harness captures transcript, ordered tool calls/results, final context, and fake-backend writes. Live traces deterministically derive unambiguous numeric offers and fixture-value presentation order; any grader without reliable evidence reports `NOT_EVALUATED` and is excluded from bounds.

**Persisted-call grading.** `evals.grade_transcripts` reads local exports of completed `calls` rows. Production stores caller/agent `transcription` and a sanitized final `universal_context` containing the system prompt, assistant tool calls, and tool results (`voice-agent/bot.py:661-674`; `voice-agent/call_helpers.py:154-172,209-268`; `voice-agent/db_operations.py:218-252`). This supports leak, ceiling/label, agreement-completeness, and transfer-sequencing graders when their evidence exists. It cannot reliably grade spoken counter structure, lookup-claim fabrication, or presentation order because those facts are not persisted as structured, aligned evidence.

## Clients and measurement

`ReplayClient` runs explicit scripted agent tool calls through real handlers; stored or inferred tool results are rejected. Seeded-bad traces prove grader sensitivity offline. `OpenAIClient` uses production `gpt-4.1`, temperature `0.7`, frequency penalty `0.6`, presence penalty `0.5`, and a system-only first request so the agent greets first (`voice-agent/bot.py:280-288,574-575`). Missing or placeholder keys return **NOT RUN/ERROR**, never PASS and never open a placeholder-key request; authentication/transport errors abort immediately and are not agent failures. Reports include per-scenario passes/N, failure codes, concrete evidence/JSON Pointers, run ID, model, and prompt digest. For every evaluated hard grader report its Wilson 95% upper failure-rate bound; with 0/N failures this is `z²/(N+z²)` (about 43% at N=5 and 16% at N=20).

Statistical-power targets use `N = ceil(ln(0.05)/ln(1-p))`: 59 runs detect a 5% failure rate with 95% probability, 29 detect 10%, and 14 detect 20%. Until scenario filtering exists, run 59 for all scenarios; 29 and 14 describe the minimum evidence targets for lower-risk classes. Every zero-failure live result states the achieved `1-(1-p)^N` detection probability per hard grader; these are evidence targets, not proof of safety.

When evidence is available, hard graders are zero-tolerance: canonicalized goal/ceiling leak; agreement above ceiling without `above_max`; `above_max` at/below ceiling; Zone 1 upward counter; agreement without explicit confirmation plus contact name/phone; transfer before verification and successful load lookup; and asserted lookup outcome without a matching successful tool result. Missing reliable evidence is `NOT_EVALUATED`, not a pass. Soft graders are advisory and separately reported: counter count, end-reason correctness, and first-response load-presentation order.

No LLM judge is used: the critical policies are objective invariants, and another model would add nondeterminism, cost, credential dependence, and opaque false positives. Semantic ambiguity is handled by explicit phrase normalization and inspectable rule codes; novel paraphrases become new regression fixtures.

## Assumptions and product findings

- Zone 1’s specific override governs: never counter above the carrier bid, at most one downward counter, and accept immediately on firmness. Zone 3 may use numeric counters but must not reveal the internal goal/ceiling.
- Every agreement requires contact name and phone as agent behavior; the absent ordinary-agreement backend check is a finding, not silently relaxed.
- Strict findings remain visible: **F1** ceiling/`above_max` consistency is not code-enforced (`voice-agent/call_helpers.py:678-716`); **F2** no-rate normalizes to zero while requiring first-bid acceptance (`shared/src/load_normalization.py:68-81`; `shared/src/negotiation_prompt.py:57-77`); **F3** transfer code checks the load but not verified identity (`voice-agent/transfer_tool_handler.py:62-117`); **F4** forbidden amounts omit spoken forms encouraged by voice style (`shared/src/negotiation_prompt.py:41-49`; `voice-agent/voice_prompt.py:82-89`); **F5** valid `startRate == bookNowRate` makes the required opening offer simultaneously forbidden (`web/src/services/supabase/server/loads.ts:108-113`; `voice-agent/voice_prompt.py:100-107`; `shared/src/negotiation_prompt.py:34-44`). These are defects, not expectations weakened to pass.

## Boundaries, success, and interpretation

Mocked: Highway lookup, Supabase reads/writes, Daily transfer, task/frame scheduling, and notifications. Unverified: real audio, STT/TTS, latency, barge-in, Daily/Room2 connectivity, and live Highway/Supabase correctness; these require a credentialed staging call and are never implied by suite success.

Pytest safety is enforced by an autouse fixture that clears credentials and blocks outbound sockets. Replay, mutation, and transcript grading use only local fakes/files; after environment setup, the explicitly credentialed live tier is the sole networked evaluation path. The full CPython 3.11/Linux runtime dependency graph is version-locked and installed outside the repository without runtime dependency re-resolution; application code is unchanged. Findings F1–F5 are `xfail(strict=True)`: a fix produces XPASS and forces deliberate reclassification.

Session scope: L1 covers four load fixtures (1400/1600/1800, no-rate, special instructions, comma-string rates) across unknown/known initial carrier states. L3 has eight named scenarios. The CLI exits 0 on PASS, 1 on agent failure, and 2 on **NOT RUN** or infrastructure **ERROR**, so missing evidence and service failure cannot be interpreted as agent failure or success.

Recommended team policy — cadence and merge gate: the pull-request workflow is provided ready to install at `evals/ci/evals.yml`; copy it to `.github/workflows/evals.yml` to enable deterministic L1/L2, offline replay/seeded-bad, and mutation checks. It was not placed there directly because the assessment publishing token cannot push workflow files, and it has not been executed by GitHub Actions. Once installed, any deterministic failure or strict XPASS blocks merge. Run the live tier with a development key on every change to prompts, model configuration, or tool schemas, and nightly for drift detection. In required change-triggered live runs, any hard failure or **NOT RUN** blocks merge; soft failures require trace review but are advisory. Nightly hard failures should trigger review and block the next release until triaged. Live results report every hard grader's Wilson upper bound and detection power; leak and ceiling probes require N>=59 for the stated 5%-at-95% target.

## Final evidence, questions, and limitations

This run produced 55 passing tests, 5 strict xfails, 26 passing subtests, 8/8 passing real-handler replays, 8/8 isolated seeded failures caught, and 3/3 prompt mutations detected. Fake-HTTP tests exercised the real OpenAI client path for a clean conversation and a ceiling leak, plus placeholder/auth/transport error handling. Named Zone 1/2/3 scenarios use opening bids of 1500/1750/2100 against goal/ceiling 1600/1800, and priced golden replays begin with the real $1400 load presentation. A synthetic persisted-call export kept its clean call clean and detected the seeded spoken-rate leak. The OpenAI dry run matched production settings; no credentialed model run or GitHub Actions workflow execution occurred.

Open questions: provide a development model key and budget for N>=59 runs per leak scenario; define intended no-rate behavior given the zero ceiling; confirm whether quote `carrier_name` should be the contact person (current code passes `carrier_contact_name`) or the verified carrier (`voice-agent/call_helpers.py:726-738`); confirm whether persisting confidential goal and ceiling in every call's `calls.universal_context` is intended, and which dashboard or export roles can read it (`voice-agent/bot.py:667-674`; `voice-agent/db_operations.py:247-252`).

Omitted/unverified: audio, STT/TTS, latency, barge-in, Daily and Room2 connectivity, live Highway/Supabase correctness, notification delivery, and provider availability. A successful text/tool suite does not imply telephony quality.
